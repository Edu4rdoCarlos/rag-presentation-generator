# Agent3 — Manual Validation (Reflection Pattern)

## Objective

The purpose of this validation was to manually test the behavior of Agent3 (`Documenter & Critic`) and verify whether the Reflection Pattern was correctly implemented.

Agent3 is responsible for:

* Generating the final structured testing documentation.
* Performing a self-review pass over the generated strategy.
* Detecting missing risks, missing edge cases, weak justifications, inconsistent criticality, or irrelevant testing recommendations.
* Returning `REVER_ESTRATEGIA` whenever the generated strategy is incomplete or inconsistent.
* Returning `APROVADO` when the strategy is coherent, sufficiently covered, and aligned with QA/security expectations.

---

# Agent3 Responsibilities

## Responsibilities

* Compile all cumulative state data into the final documentation.
* Validate consistency between:

  * identified risks
  * criticality
  * recommended test types
  * prioritized scenarios
  * justification
* Detect missing QA/security concerns.
* Trigger a reflection loop when necessary.

## Writes to State

* `final_documentation`
* `reflection_logs`
* `reflection_iteration`

---

# Reflection Pattern

Agent3 implements the Reflection Pattern.

Instead of simply generating documentation, the agent behaves as a reflective reviewer capable of:

1. Reviewing the generated testing strategy.
2. Identifying missing or weak QA/security coverage.
3. Rejecting incomplete strategies through `REVER_ESTRATEGIA`.
4. Requesting refinement before allowing the workflow to finish.
5. Approving only strategies considered sufficiently complete.

This creates an iterative QA validation cycle inside the multi-agent workflow.

# Prompt Adjustment After Manual Validation

During manual validation, Agent3 initially suggested session-related concerns such as refresh token, logout, session, or MFA even when those flows were not explicitly part of the tested feature.

To reduce false positives, the reflection prompt in `app/agents/documenter_critic.py` was refined with the following instruction:

```text
Evite falso positivo: nao exija refresh token, logout, sessao ou MFA quando a feature, regras, riscos ou dependencias nao envolverem explicitamente esses fluxos.
```

This adjustment does not change the Agent3 execution flow, state updates, or routing behavior. It only improves the review criteria used during the reflection step.

The goal was to make Agent3 stricter about real strategy gaps while avoiding rejection based on requirements outside the feature scope.
